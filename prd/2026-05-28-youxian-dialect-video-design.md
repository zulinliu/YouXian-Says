## 0.1 用户确认后的修订决策（2026-05-28）

本版方案按最新评审确认做如下收敛：

| 决策项 | 最新结论 | 对方案的影响 |
|---|---|---|
| MVP 范围 | 先做“每周 3 条 + 抖音/视频号”，稳定后再四平台日更 | 所有自动化、成本、数据闭环先按小规模验证设计，避免一开始追求全平台无人值守 |

| 发布模式 | 先发布前用户确认，稳定后再无人值守 | 发布流程默认进入待确认队列，不直接自动发布 |

### 1.1 目标

打造一个以攸县方言为核心特色的短视频内容生产体系。MVP阶段先实现个人独立操作的每周3条稳定输出，优先覆盖抖音和视频号；当选题、制作、审核、数据闭环稳定后，再扩展到四平台日更。

### 1.2 核心约束

| 维度 | 约束 |
|------|------|
| 内容形式 | AI数字人 + 攸县方言配音 |
| 发布平台 | MVP优先抖音、视频号；稳定后扩展快手、小红书 |
| 产能目标 | MVP每周3条；稳定后日更 |
| 团队规模 | 个人独立操作 |
| 方言能力 | 先使用本人攸县方言声音克隆；后续只扩展有明确授权的其他声音 |

## 二、全局架构

### 2.1 闭环系统（Agent自主驱动）

**核心原则：Agent全流程自主执行，用户仅介入创意共创、成片审核、发布确认三个环节。MVP默认发布前人工确认，不启用无人值守。**

```
Phase 0: 基础设施（一次性投入，Agent辅助）
  ├── 声音克隆（本人声音 + MiMo VoiceClone/TTS 主线，外部语音仅作后续横评）
  ├── 虚拟本地人设创建（先完成人设/头像/口播风格，HeyGen接口预留，采购后接入）
  ├── B-roll视频生成接口预留（Runway/Veo/Kling等先做适配器，采购后实测）
  └── 视频合成模板建立（FFmpeg脚本）

Phase 1: 选题共创 ← 🧑 用户介入
  用户给出想法 → Agent自主检索+发散创意 → 用户选择确认

Phase 2-5: 内容生产 ← 🤖 Agent全自主
  脚本创作 → 分镜设计 → 配音生成 → 数字人视频 → 后期合成
  （用户不参与分镜和剪辑，仅审核最终成品）

Phase 6: 发布审核 ← 🧑 用户介入
  Agent排期+适配 → 用户确认 → 分发；稳定后再开放无人值守

Phase 7: 数据闭环 ← 🤖 Agent全自主
  自动采集数据 → AI分析 → 反馈到下周选题
```

MVP阶段用户每周时间投入：
- 选题共创：约10分钟（提供想法+选择确认）
- 成品审核：约20-40分钟（MVP审核3条视频，提出修改意见，反馈修正）
- 发布确认：约10-20分钟（确认排期，审核发布效果）
- 合计：MVP约40-70分钟/周（含审核反馈和修改），其余全部Agent自主完成；日更阶段再按60-90分钟/周估算

### 2.2 市场判断

攸县方言短视频目前处于蓝海阶段：
- 暂无头部方言账号
- 内容供给量极少
- 差异化空间极大
- 本地70万人口+外攸县人群构成潜在受众
- 存在显著的先发优势窗口期

## 三、Phase 0 — 基础设施搭建

### 3.1 方言声音克隆

| 项目 | 详情 |
|------|------|
| 工具 | **MiMo V2.5 TTS VoiceClone**（本人声音主线）+ **MiMo VoiceDesign/TTS**（角色与草稿）+ **ElevenLabs/Cartesia/OpenAI TTS**（后续小额横评）+ **MiniMax Speech 2.8**（最后兜底/基线） |
| 输入 | 参考音频上传至对应官方平台，用于声音克隆 |
| 优势 | 优先使用已购小米官方语音能力，无需自备算力和训练；外部高质量语音 API 用于小米效果不足时横评，MiniMax 只作为最后备用 |
| 推理 | 文字→攸县方言语音，通过API调用，云端推理 |
| 外部候选 | ElevenLabs、Cartesia、OpenAI TTS 在 MiMo 方言效果低于 3.5/5、或需要更强情绪/角色声线时小额横评；MVP 不走自训练路线 |

录音要求：
- 安静环境，手机或话筒录制
- 内容覆盖：日常对话、美食介绍、景点描述、民俗讲述、幽默段子
- 每段3-10分钟，总计30-60分钟素材
- 情感多样：平静讲述、热情推荐、幽默调侃

### 3.2 AI数字人形象

| 方案 | 工具 | 成本 | 效果 |
|------|------|------|------|
| 主选 | HeyGen Avatar IV/V | 按官网 API/PAYG 或套餐核算 | 质量和成熟度优先，适合 30-90 秒口播；上线前确认 API 权限、9:16、并发和每分钟成本 |
| 备选1 | Tavus | 按套餐/API核算 | API 产品化强，适合后续互动数字人或 HeyGen 成本过高时横评 |
| 备选2 | D-ID / AKOOL | 按 API credits 核算 | 单图说话、低成本口播、营销素材兜底 |
| 国内兜底 | 腾讯智影 / 剪映数字人 | 按平台套餐核算 | 中文模板和人工半自动方便，但 API 自动化需实测 |

策略说明：数字人不按国内外划分，按“口型质量/每分钟成本/API稳定性/竖屏适配”排序。最新决策是先不购买 HeyGen/Runway，优先完成虚拟本地人设、数字人适配器、配置页和Mock/半自动占位流程；系统稳定后再购买 HeyGen 小额额度验证。若成本、API、口型或审核限制不满足稳定生产，再横评 Tavus、D-ID 或 AKOOL。若 API 自动化受限，保留“人工上传音频到平台 + 自动下载/导入合成”的半自动流程。

### 3.3 内容素材库

| 素材类型 | 收集方式 | 工具 |

| 攸县实景照片 | 网络搜索+AI生成+少量后续实拍 | GPT-image-2 主线，Firefly/Imagen/Seedream/FLUX 横评，MiniMax image-01 最后兜底 |

### 5.1 流程

### 5.2 脚本标准模板

```
【视频标题】：xxx
【时长】：xx秒（30-90s）
【平台重点】：抖音/快手/视频号/小红书

【开头Hook - 前3秒】
（方言台词）
画面描述

【正文 - 核心内容】
分镜1：画面描述 + 台词
分镜2：画面描述 + 台词
...

【结尾CTA - 最后3秒】
（方言互动引导）
画面描述
```

### 5.3 质量要求

- 前3秒必须有强hook（方言+疑问/惊叹）
- 每15秒一个情绪转折
- 结尾必须有互动引导
- 方言表达自然，避免生硬翻译

---

### 5.4 内容质量保障机制

**方言质量：**
- 构建"普通话-攸县方言对照语料库"，覆盖常用表达、美食术语、地名俗语
- 脚本生成后必须经过用户审核方言表达，标记"不自然"的方言用法
- 方言语料库持续积累：从评论区收集本地方言用法，定期更新

**视觉质量：**
- 建立攸县实景素材库（网络搜索 + AI生成 + 后续可选实拍），分类管理（美食、景点、街景、民俗）
- 当前没有稳定实拍图来源，封面、分镜参考和缺失素材优先使用 GPT-image-2 生成；Firefly/Imagen/Seedream/FLUX 作为外部横评，MiniMax image-01 仅最后兜底
- 每条 AI 生成素材记录提示词、模型、版本、来源说明和是否用于商业发布，避免后续版权和追溯问题

**字幕翻译：**
- 采用分层策略：DeepSeek自动翻译为第一步 → 用户修正为第二步 → 评论反馈收集为持续优化源
- 记录每次翻译修正，积累方言-普通话对照表，提升自动翻译准确率

**内容查重：**
- 选题阶段搜索各平台相似内容，避免与已有爆款高度重复
- 建立"已做内容库"，记录每期选题关键词，避免自我重复
- 定期分析竞品内容方向，寻找差异化切入点

## 八、Phase 5 — 后期合成（Agent全自动）

### 8.1 Agent自动合成流程

用户不懂视频剪辑，此环节完全由Agent通过FFmpeg/moviepy脚本自动完成：

```
1. FFmpeg导入HeyGen数字人口播视频
2. FFmpeg替换/叠加MiMo方言配音；必要时使用ElevenLabs/Cartesia/OpenAI或MiniMax最后兜底音频
3. FFmpeg叠加Runway/Veo/Kling/Luma/Pika生成的B-roll画面；Hailuo仅作为兜底/基线（画中画或切换）
4. FFmpeg+GLM/DeepSeek自动生成并烧录字幕（方言原文+普通话翻译）
5. FFmpeg添加背景音乐（从预设音乐库选取）
6. FFmpeg添加品牌元素（片头/片尾/watermark模板）
7. FFmpeg导出4个平台版本：
   - 9:16（抖音/快手/视频号）
   - 3:4（小红书）
   - 16:9（B站备选）
```

### 8.2 技术实现

```python
# Agent自动合成脚本核心逻辑（伪代码）
def auto_compose(script, voice_audio, digital_human_video, b_roll_clips):
    # 1. 合并数字人+配音
    base_video = ffmpeg.merge(digital_human_video, voice_audio)
    
    # 2. 叠加B-roll
    for clip in b_roll_clips:
        base_video = ffmpeg.insert_b_roll(base_video, clip, 
            at=clip['timestamp'], duration=clip['duration'])
    
    # 3. 生成字幕（DeepSeek翻译方言→普通话）
    subtitles = deepseek.generate_subtitles(script)
    base_video = ffmpeg.burn_subtitles(base_video, subtitles)
    
    # 4. 添加音乐和品牌元素
    base_video = ffmpeg.add_bgm(base_video, select_music(script['mood']))
    base_video = ffmpeg.add_branding(base_video, BRAND_TEMPLATE)
    
    # 5. 导出多版本
    outputs = {}
    for platform in ['douyin', 'kuaishou', 'weixin', 'xiaohongshu']:
        outputs[platform] = ffmpeg.export(base_video, 
            format=PLATFORM_FORMATS[platform])
    
    return outputs
```

### 8.3 字幕处理规范

- 方言台词用普通话字幕（扩大受众）
- 特殊方言词汇用括号标注解释

- TOP3 最佳/最差内容分析
- 内容支柱效果对比
- 下周策略建议
- 自动反馈到选题系统

### 9.4 选题权重引擎

根据数据表现动态调整5个内容支柱的发布频次：
- 每周分析各支柱的平均播放量、完播率、互动率、涨粉效率
- 自动计算下一周各支柱的建议条数（高ROI支柱增加频次，低ROI支柱减少或暂停）
- 将权重调整记录反馈到选题系统，指导内容Agent生成对应数量的选题

### 9.5 策略-效果追踪表

记录每次策略调整的原因和实际效果：

| 字段 | 说明 |
|------|------|
| 调整日期 | 策略变更的时间 |
| 调整原因 | 数据表现/用户反馈/外部事件 |
| 调整内容 | 具体变更的维度（如支柱频次、发布时间、标题风格等） |
| 预期效果 | 期望达到的目标 |
| 实际效果 | 2-4周后的数据对比 |
| 结论 | 策略是否有效，是否保留 |

### 9.6 增强周报维度

周报在原有基础上增加以下分析维度：
- **发布时间效果**：统计不同发布时段的播放量差异，优化排期
- **标题点击率**：分析标题风格与点击率的相关性
- **完播率分段**：分析观众在哪个时间段流失，优化脚本节奏
- **涨粉来源**：追踪粉丝增长来源（搜索、推荐、同城、转发等）
- **跨平台对比**：同一内容在不同平台的表现差异分析

### 9.7 轻量A/B测试

利用跨平台天然A/B进行内容测试：
- 不同标题分发到不同平台，对比点击率差异
- 不同封面风格分发到不同平台，对比点击率差异
- 不同发布时间测试同一内容的效果差异
- 记录A/B测试结果，积累最优实践库

## 十一、精选模型与工具体系（按场景路由）

### 10.1 核心原则

2026-05-28 复核后，本节从“一维度一选”调整为“按场景路由”：低成本模型负责批量草稿，高质量模型负责定稿，媒体模型按效果/成本/稳定性分层。选择标准：
- New API 中转站模型不按通道来源一刀切降级；按 `channel=new_api_relay` 管理，重点监控稳定性、延迟、计费、上下文、工具调用和文件/图片接口差异
- 方言短视频场景适配度优先，方言表达必须依赖语料库和人工抽检
- 深度推理优先级固定为 **GLM-5.1 > GPT-5.5 > DeepSeek V4 Pro**，批量草稿仍用 DeepSeek Flash/MiMo 控制成本；MiniMax 只做基线对照
- 图像生成优先使用 **GPT-image-2**，因为当前图片素材主要依赖网络搜索和 AI 生成，且你已实测该模型效果最好
- 视频和数字人不按国内外划分，按效果/成本/可批量/API稳定性排序；不考虑自训练模型，因为没有 GPU 资源

### 10.4 模型Prompt适配

每个备选模型需要准备专用的system prompt模板，切换模型时自动加载对应的prompt模板：

| 模型 | Prompt适配要点 |
|------|----------------|
| **DeepSeek V4 Flash** | 输出候选时要求数量、差异点、风险标签，不要求一次成稿 |

| **DeepSeek V4 Pro** | 用于第三顺位深度推理和稳定中文定稿，必须要求结构化JSON、事实来源、方言词典引用 |
| **MiMo V2.5 Pro** | 作为二审模型，重点检查长上下文一致性、错漏和口语自然度 |
| **MiniMax M2.7** | 仅作为基线/最后兜底，提示词强调“短句、停顿、口播节奏”，不进入默认主链路 |

| **中转站模型** | 按 New API 兼容通道接入，prompt 与官方基本一致，但调用日志必须记录通道、失败率和能力差异 |

实现方式：
- 在配置文件中为每个模型维护独立的prompt模板目录
- 切换模型时，n8n工作流自动加载对应模板
- 模板包含：system prompt + few-shot示例 + 输出格式要求

## 十二、每周时间表（Agent自主驱动）

MVP按每周3条设计，稳定后再扩展到每周7条/日更。下表保留完整自动化链路，但执行数量按阶段切换。

| 环节 | 谁做 | 用户耗时 | Agent耗时 |
|------|------|----------|-----------|
| 选题共创 | 🧑用户+Agent | 10分钟 | Agent自动检索+发散 |
| 脚本创作 | 🤖Agent | 0 | 自动（DeepSeek草稿 + GLM-5.1/DeepSeek Pro定稿） |
| 分镜设计 | 🤖Agent | 0 | 自动（GLM-5.1 + GPT-image-2参考图） |
| 方言配音 | 🤖Agent | 0 | 自动（MiMo VoiceClone/TTS优先，ElevenLabs/Cartesia/OpenAI横评，MiniMax Speech 最后兜底） |
| 数字人视频 | 🤖Agent | 0 | MVP使用虚拟本地人设占位/半自动；采购后接入HeyGen API |
| 后期合成 | 🤖Agent | 0 | 自动（FFmpeg脚本） |
| 成品审核 | 🧑用户 | 40-60分钟 | — |
| 发布确认 | 🧑用户 | 10-20分钟 | MVP用户确认后分发；稳定后再无人值守 |
| 数据分析 | 🤖Agent | 0 | 自动（结构化数据表 + DeepSeek日报 + GLM-5.1周报） |
| **合计** | — | **60-90分钟/周（含审核反馈和修改）** | — |

Agent端执行时间（自动运行，无需等待）：
- 脚本创作：MVP 3条×2分钟 = 6分钟；日更阶段 7条×2分钟 = 14分钟
- 分镜生成：MVP 3条×3分钟 = 9分钟；日更阶段 7条×3分钟 = 21分钟
- 配音生成：MVP 3条×30秒 = 1.5分钟；日更阶段 7条×30秒 = 3.5分钟
- 数字人渲染：MVP先占位/半自动；采购后按实测耗时估算，日更阶段约7条×8分钟 = 56分钟
- B-roll生成：MVP先用图片动效/已有素材占位；采购后按实测耗时估算，日更阶段约7条×5分钟 = 35分钟
- 后期合成：MVP 3条×5分钟 = 15分钟；日更阶段 7条×5分钟 = 35分钟
- Agent总耗时：MVP约1-2小时（含占位/半自动环节）；采购媒体模型并进入日更后约4-5小时，全部后台自动运行

任务依赖说明：
- 脚本+分镜必须串行执行（分镜依赖脚本内容）
- 配音和B-roll可并行生成（互不依赖）
- 数字人渲染依赖配音完成后才能启动（口型同步需要音频输入）

## 十六、合规注意事项

### AI生成内容声明
- 发布时自动添加"本视频使用AI技术制作"标签
- 各平台按政策要求勾选AI声明选项（抖音、快手、视频号均有AI内容标识功能）
- 视频片尾统一添加AI制作说明

### 方言敏感词
- 建立攸县方言敏感词黑名单，覆盖政治、宗教、歧视、低俗等类别
- 脚本生成后自动扫描敏感词（Agent内置过滤模块）
- 定期更新敏感词库，关注平台政策变化

### 声音克隆合规
- 录音时同步录像留存授权证据
- 账号简介注明"声音已获得本人授权"
- 仅克隆本人声音，绝不克隆他人声音

### 虚假宣传防范
- 美食类内容标注"AI整理，仅供参考"
- 避免绝对化用语（如"最好吃""世界第一"）
- 景点推荐基于真实信息，AI生成内容需人工核实事实准确性
- 历史/风俗内容以爆款共创优先，事实来源作为质量护栏：明确事实尽量核验；民间说法可用“听老一辈讲/攸县不少人晓得这个说法”等表达；避免编造官方结论、人物身份、历史定论和功效承诺

### 数据备份
- 每日自动备份 data/ 目录和模型文件到异地存储
- 备份脚本由n8n定时任务触发
- 保留最近30天的增量备份和每月的完整备份

### Cookie安全
- Playwright的Cookie加密存储，不以明文保存在代码仓库中
- Cookie定期自动刷新（每周），过期自动提醒
- 发布账号的登录凭证使用环境变量管理，不硬编码

### 发布后审核监控
- 视频发布后48小时内，运营Agent自动监控视频状态
- 审核不通过时自动分析原因（标题敏感/画面违规/版权问题），生成修改建议
- 同一视频连续3次审核不通过，暂停自动发布并通知用户手动处理

### 通用合规
- 素材版权：网络素材需确认版权状态，优先使用AI生成或自有素材
- 音乐版权：使用剪映自带音乐库或明确免版权的音乐
- 方言表达尺度：避免方言表达的歧义引发争议，敏感话题需额外审核
## 十七、评审发现与本版优化清单

| 评审发现 | 风险 | 本版优化 |
|---|---|---|
| 原方案一开始追求四平台日更 | 产能、质量和成本同时失控 | 改为MVP每周3条，优先抖音和视频号，稳定后再扩展 |
| 原方案默认需要HeyGen/Runway | 还未采购时无法搭建和验证 | 改为先完成适配器、Mock/半自动占位和配置页，采购后再接真实服务 |
| 数字人形象路线不够明确 | 真人授权、虚拟形象、平台接口混在一起 | 改为先虚拟本地人设，再真人授权形象 |
| 声音克隆扩展边界不清 | 其他人声音存在授权风险 | 改为先本人声音克隆，其他人声音必须后续单独授权 |
| 历史/风俗事实要求过硬 | 可能压制爆款创意和民间表达 | 改为爆款共创优先，来源作为质量护栏和风险分级，不做硬阻塞 |
| 发布流程过早自动化 | 平台风控、审核失败、账号安全风险高 | 改为发布前用户确认，稳定后再启用无人值守 |
| 模型切换只说“可切换”不够 | API URL、Key、模型名、中转站能力差异可能遗漏 | 明确模型注册中心必须支持API Base、Key、Model Name、Channel、能力开关、连接测试和调用日志 |
| 数据闭环容易停留在周报文字 | 无法指导下一轮选题 | 明确周报必须输出内容支柱ROI、评论洞察、模型成本/失败率和下周策略 |
